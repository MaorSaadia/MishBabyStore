# MishBaby Repository Instructions

- Never modify, commit to, or push directly to the production branch (`main` unless repository configuration explicitly says otherwise).
- Work only on an explicitly named feature branch. Confirm the branch and working-tree status before editing.
- Preserve the existing MishBaby brand colors unless a task explicitly authorizes a change.
- Never print, copy into documentation, or commit environment-secret values. Refer to environment variables by name only.
- Do not introduce eBay or Etsy into architecture, data, retailer types, navigation, or seed content.
- Keep retailers and affiliate networks as separate domain concepts. For example, Target is a retailer and Impact.com is an affiliate network.
- Keep MishBabyGuide separate from MishBaby; do not merge their content or product architectures unless explicitly instructed.
- Run lint, TypeScript checking, tests, and a production build when applicable and available. Report exact commands and results.
- Report every changed file and avoid unrelated refactoring.
- Prefer small commits with descriptive messages, but never commit or push unless explicitly instructed.
- Never deploy to production or change production deployment settings without explicit instruction.
